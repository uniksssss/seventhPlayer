# Седьмой игрок

Мобильная студия публикаций фан-сектора волейбольного клуба «Уралочка-НТМК».

## Запуск

Требуется Node.js 22.12+ и npm. Проверенная версия указана в `.nvmrc`.

```sh
npm install
npm run dev
```

Vite выведет локальный адрес и адрес для доступа с телефона в той же Wi-Fi сети.

```sh
npm run typecheck # проверка TypeScript
npm run build     # проверка TypeScript и сборка в dist/
npm run preview   # просмотр собранного приложения
npm test          # проверки валидации и общих утилит
npm run format    # форматирование исходников и тестов
```

## Стек и структура

Vite, React, TypeScript и Emotion. Стили — через `@emotion/styled`, общая тема — через `ThemeProvider`.

- `src/app/` — приложение, глобальные стили и типизированная тема.
- `src/pages/` — сборка экранов из компонентов, навигация и прокрутка к ошибке.
- `src/features/posts/` — категории публикаций и карточки выбора.
- `src/features/match-day/model/` — типы, начальные значения, каталог логотипов, валидация и хук `useMatchDayEditor` с состоянием редактора.
- `src/features/match-day/ui/` — `MatchDayForm` с полями и `MatchDayPreview` с превью и кадрированием.
- `src/features/match-day/services/` — функции рендера и экспорта макета; не зависят от React.
- `src/features/birthday/` — отдельные модель, валидация, хук состояния, форма и сервис макета дня рождения.
- `src/shared/ui/` — переиспользуемые загрузка изображения, переключатель темы, ошибки и стили элементов формы.
- `src/shared/ui/poster/` — общий Canvas-превью с обработкой загрузки/ошибок и оформление экранов редактора.
- `src/shared/lib/` — чтение изображений, скачивание PNG, атрибуты ошибок и прокрутка к полю.
- `tests/` — проверки валидации и общих утилит на встроенном Node.js test runner.

Стили компонентов лежат рядом в `*.styles.ts`. Общий код в `shared/` не импортирует страницы или конкретные макеты. Новые редакторы могут использовать общие элементы формы и работу с изображениями; их данные, правила проверки и координаты рендера остаются внутри соответствующей feature.

Цвета и базовые параметры оформления находятся в `src/app/theme.ts`. На компьютере приложение сохраняет мобильную ширину.

## Текущий этап

Карточка «Матч-день» открывает редактор (`#/match-day`). Форма меняет тур, дату, время, место проведения, лигу, фон, фото и логотипы команд. Превью и экспорт PNG 2160×2160 используют один Canvas-рендер и локальные файлы Roboto Condensed. До загрузки фото и логотипов показываются пунктирные области; для экспорта нужны все изображения и поля матча. Превью закреплено при прокрутке, настройка кадрирования находится сразу под ним. Фон переключается тумблером; в тёмной теме используется светлый строчный логотип.

Каталог готовых логотипов находится в `src/features/match-day/model/teamLogos.ts` отдельно для каждой лиги. При выборе первой команды второй автоматически становится «Уралочка» выбранной лиги; если первой выбрана «Уралочка», вторую нужно выбрать самостоятельно. Правило применяется и при загрузке своего логотипа первой команды. Вторую команду можно поменять вручную. Загруженные пользователем PNG/JPG/WebP добавляются в список текущей лиги и доступны до выхода из редактора. При смене лиги выбранные логотипы сбрасываются. Черновики и загрузки пока не сохраняются после выхода или перезагрузки; сервера нет.

Карточка «С днём рождения» открывает редактор (`#/birthday`) с именем, фамилией, номером игрока и загрузкой фотографии. Положение фото настраивается прямо под превью. Поздравление и красный декор сохраняются из `public/день рождения.png`; исходные зелёные подписи очищаются только в областях имени и номера, затем отрисовываются новые значения. Фотография заполняет свою рамку без изменения пропорций, красные штрихи остаются поверх неё. До загрузки фото показывается пунктирная область; для сохранения фото обязательно. Длинное имя с фамилией уменьшается по ширине. Превью и экспорт PNG 2160×2160 используют один сервис. Кнопка скачивания проверяет поля и переводит фокус к первой ошибке. Черновик действует до выхода из редактора.

Декоративные линии дня матча воссозданы по референсу. Для окончательной подгонки нужны исходное фото и, при необходимости, чистый фон макета. Другие типы публикаций пока не имеют редакторов.

## Публикация на GitHub Pages

В проекте настроен workflow `.github/workflows/deploy-pages.yml`. Он проверяет тесты,
собирает приложение и публикует `dist/` при отправке изменений в ветку `main`.

1. Загрузите проект в GitHub-репозиторий в ветку `main` (без `node_modules/` и `dist/`).
2. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Во вкладке **Actions** запустите **Publish to GitHub Pages → Run workflow**,
   если первый запуск произошёл до настройки Pages.
4. После успешной публикации адрес появится в **Settings → Pages** и в результате deployment.

Для бесплатного GitHub Pages репозиторий должен быть публичным.
Если основная ветка называется иначе, измените `branches` в workflow.
Пути к ресурсам относительные: сайт работает и в подпапке репозитория, и на отдельном домене.
